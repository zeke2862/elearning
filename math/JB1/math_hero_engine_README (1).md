# 數學勇者角色建立與戰鬥規則引擎

## 檔案內容

- `math_hero_engine.txt`：JavaScript 規則引擎原始碼，可複製成 `.js` 檔案供遊戲載入。
- 本引擎只處理角色建立、能力值、招式抽取、招式費用與戰鬥計算；登入、畫面、資料庫存檔及金幣發放仍由遊戲主程式負責。

## 一、角色建立

### 姓名數值

- 英文姓名：忽略空格及非英文字母，依 A=1、B=2……Z=26 加總。
- 中文姓名：因程式無法可靠判斷不同字體、異體字的筆劃，需由玩家輸入姓名總筆劃。
- 本命餘數 = 姓名數值除以 4 的餘數。
- 餘數 0、1、2、3 分別對應聖騎士、刺客、狂戰士、大魔導士。
- 計算能力值時，餘數 0 改用基礎值 4；角色流派仍然是聖騎士。

### 擲兩顆骰子

`rollTwoDice()` 會產生兩顆 1–6 的骰子及其總和。`createCharacter()` 也允許傳入 `diceResult`，方便測試或由遊戲畫面自行擲骰。

### 六大能力值

| 能力 | 初始公式 | 流派加成 |
|---|---|---|
| HP | 基礎餘數 × 10 + 骰子和 × 5 | 狂戰士 +30 |
| ATK | (基礎餘數 + 骰子和) × 2 | 無 |
| DEF | 基礎餘數 × 3 + 骰子和 | 聖騎士 +10 |
| SPD | 12 − 骰子和 + 基礎餘數 × 2 | 刺客 +15 |
| MATK | 基礎餘數 × 骰子和 | 大魔導士最後 ×2 |
| MDEF | (基礎餘數 + 6) × 2 | 不受骰子影響 |

建立角色後，物件包含 `stats`、`currentHP`、`skills`、已研發招式數及下一次研發費用等欄位。

## 二、招式研發（抽卡）

每次研發先檢查金幣是否足夠，成功才扣款並把招式放入角色的 `skills`。

### 招式類型骰

- 1–2：物理系
- 3–4：魔法系
- 5–6：速度特化系

### 稀有度骰

原始說明同時要求「骰子決定系列」及「每系列有三種稀有度」，但單顆骰子分成三種系列、又各自對應三種稀有度，無法單靠同一個點數無歧義地完成。因此本版本採用**兩次擲骰**：
- 第一次決定系列。
- 第二次決定稀有度：1–3 普通、4–5 強力、6 傳說。

此設計可調整；若希望只擲一顆骰子，需另行指定六個點數與九種「系列 × 稀有度」組合的對應方式。

## 三、招式費用遞增

因需求只指定「費用隨研發次數提升」，未指定遞增幅度，本版本採用線性遞增：

- 第 1 次：50 金幣
- 第 2 次：100 金幣
- 第 3 次：150 金幣
- 第 N 次：50 × N 金幣

可在 `DEFAULT_RULES` 調整 `skillBaseCost` 及 `skillCostIncrease`。`learnSkill()` 會回傳本次費用、剩餘金幣、抽到的招式與下次費用。

## 四、招式效果與傷害

### 物理系

- 橫掃千軍：ATK × 1.2 − 對手 DEF。
- 裂地重擊：ATK × 1.8 − 對手 DEF；使用者速度暫時 −3。
- 崩天神皇斬：ATK × 2.5 − 對手 DEF。

### 魔法系

- 大熱計：MATK × 1.2 − 對手 MDEF。
- 落雷轟擊：MATK × 1.6 − 對手 MDEF；對手速度暫時 −5。
- 九天玄雷破：MATK × 2.5 − 對手 MDEF。

### 速度特化系

- 疾風雙刃：ATK + 自己的有效 SPD，無視對手防禦。
- 神速術：不造成傷害，自己的 SPD 暫時 +15，並標記速度差符合條件時的下一回合三連擊；三連擊標記會在 `attacksThisTurn()` 實際判定成功時消耗。
- 迅雷閃光刺：有效 SPD × 3，無視對手防禦。

所有造成傷害的攻擊，最後傷害至少為 1，並向下取整。`calculateDamage()` 會更新受擊者的 `currentHP`。

## 五、速度比例與累積行動值（已依最新規則修改）

不再使用「速度差 10／20 就直接增加攻擊次數」的舊規則，而是依雙方有效 SPD 的比例決定先後順序，並保留尚未輪到攻擊的累積行動值。

- 例如 A 的 SPD=100、B 的 SPD=50，比例為 2:1，長期行動順序會按 A、B、A 循環，亦即每三次行動約為 A 攻擊兩次、B 攻擊一次。
- 每次判定時，雙方的累積行動值各增加自己的有效 SPD；累積值較高者取得下一次攻擊，並從該角色的累積值扣除雙方速度總和。
- 累積餘額會保留，因此速度差距不大時會自然累積到後續攻擊，不會每次判定就把進度歸零。
- 戰鬥結束時呼叫 `resetInitiative(a, b)`，即可重置雙方行動值。暫時速度加成／減益則由主程式在效果到期時呼叫 `endTurn()`。
- `nextAttacker(a, b)` 回傳下一位攻擊者、目標、速度比例及累積值。若遊戲要讓某位角色在同一個行動階段連續攻擊兩次，主程式應在該階段重複執行傷害計算，再呼叫 `nextAttacker()` 決定下一位角色。

神速術會設定三連擊標記；`nextAttacker()` 在該角色輪到時消耗標記並回傳 `grantedTripleAttack`。主程式可據此讓該角色在該次行動連續攻擊三次。

## 六、整合方式

```js
// 1. 建立角色；中文姓名需提供筆劃總和
const hero = MathHeroEngine.createCharacter({
  name: "小明",
  chineseStrokeTotal: 21
});

// 2. 研發招式（假設玩家有 200 金幣）
let gold = 200;
const draw = MathHeroEngine.learnSkill(hero, { gold });
if (draw.success) gold = draw.goldRemaining;

// 3. 依速度比例決定下一位攻擊者
const turn = MathHeroEngine.nextAttacker(hero, enemy);
const battleResult = MathHeroEngine.calculateDamage(turn.actor, turn.target);

// 4. 使用已學招式
const skill = hero.skills[0];
const skillResult = MathHeroEngine.calculateDamage(hero, enemy, skill);
```

請將程式原始碼另存為 `math_hero_engine.js`，並在 HTML 主程式中先載入該檔案，再使用 `MathHeroEngine`。若專案採用 ES Module，需依目前專案架構調整匯出方式。

## 七、目前採用的明確假設

1. 中文姓名筆劃由使用者輸入，避免錯誤判斷。
2. 招式類型及稀有度分別擲骰。
3. 研發費用每次增加 50 金幣。
4. 一般速度差門檻為 10、20；神速術另有三連擊條件。
5. 速度減益與加成由戰鬥回合管理；主程式應在適當時機呼叫 `endTurn()`，神速術的三連擊標記會在 `attacksThisTurn()` 判定成功時消耗；請由主程式在回合結束時呼叫 `endTurn()` 清除暫時速度加減。
